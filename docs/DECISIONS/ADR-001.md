# ADR-001: OS Strategy Pattern for Metrics Collection

## Status

Accepted

## Context

The agent must collect host metrics (CPU, memory, processes, services) on Linux, macOS, and Windows. Each OS uses different shell commands and output formats (`ps`, `systemctl`, `tasklist`, `launchctl`, etc.).

## Decision

Use the **Strategy pattern** with a shared `MetricsCollector` interface and OS-specific implementations:

- `MetricsCollector` — contract for all platforms
- `AbstractMetricsCollector` — Template Method for JMX-based CPU/memory
- `linux/`, `mac/`, `windows/` packages — platform-specific process/service collectors
- `MetricsCollectorConfig` — selects `@Primary` bean via `OperatingSystemCondition`

Docker container collection is a separate optional component (`DockerContainerCollector`) with its own schedule and cache, not part of the OS strategy interface.

## Consequences

**Positive:**
- Clear separation: orchestration (`InstanceMetricsSender`) vs collection (collectors)
- Easy to add platform-specific logic without touching shared code
- Spring conditional beans enable compile-all, run-one deployment

**Negative:**
- Mac implementation duplicates some logic (`MacProcessCollector` exists but is unused — see TD-002)
- All platform JARs ship together (acceptable for a small agent)
