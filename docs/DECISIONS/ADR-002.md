# ADR-002: Log-First Output (HTTP Push Deferred)

## Status

Accepted

## Context

Collected metrics must reach downstream systems. Options considered:

1. **JSON log file** — write `MetricsPayload` to application log
2. **HTTP POST** — push to remote metrics API (`metrics.api.endpoint`)
3. **Both** — log locally and push remotely

The project has `RestTemplate` configured and `metrics.api.endpoint` in `application.properties`, but HTTP send was never wired.

## Decision

**Phase 1 uses log-first output only.**

- `InstanceMetricsSender` serializes `MetricsPayload` to JSON and writes via `log.info`
- Log file path configured via `logging.file.name` (default: `metrics-collector.log`)
- HTTP push deferred to **Phase 2** (requires V12 user approval)

Rationale:
- Simplest deployment — no remote dependency for initial operation
- Log shippers (Fluent Bit, Filebeat, etc.) can ingest JSON logs without code changes
- Agent remains resilient when metrics server is unreachable (V11)

## Consequences

**Positive:**
- Agent runs standalone on any host
- Smoke test can assert payload without mock HTTP server
- Clear phase boundary for HTTP integration

**Negative:**
- `RestTemplate` is currently unused (TD-001)
- Real-time push requires Phase 2 work

## Future (Phase 2)

When approved, HTTP push should:
- Not replace log output (dual write initially)
- Fail gracefully without crashing scheduler
- Be covered by unit tests with mocked `RestTemplate`
